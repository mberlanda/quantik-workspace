- Decisions and assumptions:
  - Labeled the drawer "Advanced" (not "Settings", not "Lab" — avoided reusing "Lab" since the page is already titled "Game Lab" and a second use felt confusing).
  - `error-message` (the QFEN validation message) moved along with `qfen-input` even though the packet's list doesn't name it explicitly — it's tightly coupled to that field (`aria-invalid` is set on the textarea on parse failure) and leaving a naked error paragraph on the main surface with no visible input to explain it seemed worse than moving it with its control.
  - `player-name` and `opponent-0`/`opponent-1` (the trained-model pickers) were **not** moved — the packet's list names only the two controller selects (`player-0-controller`/`player-1-controller`), not the model pickers, which read as more central to "Play a model" mode and likely belong on V2's main surface rather than the drawer.
  - The nested "Play service endpoint" `<details>` around `service-base` was kept as-is (just relocated) rather than flattened, since collapsing it into the outer drawer's already-collapsed content seemed like unnecessary restructuring for a relocation task; V4 (styling) can revisit if a nested disclosure inside a disclosure reads badly once styled.
- **Scope deviation (flagging per "path expansion requires coordinator review"):** `test/index.test.js` was touched, outside V1's `allowed_paths` (`index.html, src/app.js, src/layout.js, test/layout.test.js`). Necessary, not optional: that test asserts the exact ordered list of `<script>` tags in `index.html` via `assert.deepEqual`, and adding `src/layout.js` as a new classic script (required for `app.js` to reach `QuantikLayout` at runtime — the whole point of the module split) changes that list. One line changed (added `"src/layout.js"` to the expected array). Following the pattern from `quantik-models-py` M1 (see its handoff entry) rather than leaving the suite red or duplicating `layout.js`'s logic inline in `app.js` to avoid the script tag. This same conflict will very likely recur for V2 (`modes.js`) and V3 (`rules.js`), which have the identical `index.html`-plus-new-module shape and also don't list `test/index.test.js` in their `allowed_paths`.
