A brand-new visitor still gets the neutral prompt: `DEFAULT_PROFILE.mode` is `""`, which matches none of the four ids, so no button renders selected, and the controller selects keep whatever `index.html` already sets them to — nothing regresses for someone who never touches the chooser at all.
  - **O2 → D8 (recorded in `decisions.md`): a classical-only roster is offered under "Play a model," not hidden or disabled.** `applyMode` unconditionally sets `player1` (or whichever seat) to the `"service"` controller; the opponent picker already shows whatever `GET /api/opponents` returns, with no special-casing needed for "no staged models" — it already degrades to the six classical engines on its own. Zero new branches, and it matches `initiative.md`'s explicit "must read as a deliberate state, not a failure" language.
  - `player0`/`player1` in `applyMode`'s `profile` parameter is **not** the `settings.js` profile object — it's a lightweight `{player0, player1}` shape describing the *current controller selection*, built fresh in `app.js` from the live select values (`currentControllers()`). Kept separate from the persisted settings profile (which only stores the *chosen mode id*, not the resulting controllers) so the two concerns — "what mode did you pick" and "what controllers does that imply right now" — don't get tangled.
  - Manually changing a controller select in the drawer after picking a mode does **not** clear the mode highlight — the chooser keeps showing the last-clicked mode even if the drawer has since overridden it.
