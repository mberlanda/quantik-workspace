# quantik-models-py

## Objective

Be the parity oracle. Expose the fixtures and expected outputs the Rust port is checked
against. No behaviour changes here.

## Inputs

- `env/fastboard.py::encode_tensors` — the authoritative mover-relative encoder.
- `docs/architectures.md:28-44` — the correct description of the layout; the trap is
  already spelled out there.
- The published ONNX graphs and their manifests.

## Approach

Emit a small fixture set — QFENs with their expected `[9,4,4]` encoding and the
expected `policy_logits` / `value` for each published model — in a form Rust can read
without a Python runtime. Include `"A.../..../..../...."` as the discriminating case.

## Completion criteria

- The fixture set exists, is generated by a script (not hand-written), and is checked
  in with the graph hashes it was generated against.
- A Python-side test asserts the fixtures still match the current encoder, so drift is
  caught here rather than as a mysterious Rust failure.
- Handoff records the commit and the `onnx_hash` of each graph used.
