# Contributing

Start with discovery and repository ownership. Keep implementation changes in their owning repository and represent cross-repository intent as an initiative with repository tasks. Classify version occurrences; preserve historical fixtures/records; distinguish candidate from published refs.

For workspace changes run formatting, lint, tests, all validation, and CLI smoke checks. Add focused tests for every parser, command, state transition, validation/error path, and compatibility fallback. Do not push/tag/publish/open PRs as a side effect of validation or planning. Update generated files and the implementation report when behavior changes.
